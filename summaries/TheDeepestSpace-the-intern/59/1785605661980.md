## Prompt / Request
Good question — I considered this in #58 before landing on the KV approach. Here's the concrete trade-off: **Drop `pull_request_review`:** lose triggering on a review submitted with only a top-level body and no inline comments — e.g. `LGTM` or `please also check X` typed into the review summary box with Approve/Request changes, no inline comments at all. **Drop `pull_request_review_comment`:** lose triggering on inline diff comments that mention the bot when the review's top-level body is empty — e.g. reviewer leaves `fix this line` as an inline comment and submits with a blank summary. Also, multiple inline comments in one review each fire their own `pull_request_review_comment` delivery, so dropping this loses all of them, not just one. Neither event is a strict subset of the other, so cutting either one silently drops a currently-working trigger path rather than just fixing the duplicate-dispatch bug. If avoiding worker state is the priority over covering both cases, a stateless alternative: keep both events, but only act on `pull_request_review_comment` when `comment.pull_request_review_id` is present *and* skip `pull_request_review` whenever `review.body` is empty (inline-only reviews) — that removes most duplicates (review body + comment mentioning bot) without KV, at the cost of still double-firing if someone puts `` in both the body and an inline comment. Happy to switch to that if imperfect dedupe is an acceptable trade for no new state — let me know.
