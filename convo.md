## 2026-08-07: workspace-backup-on-every-run — design refined after two follow-up questions
Following PR#111, user asked for a backstop independent of the stop-hook regex: capture untracked+modified files (and the agent's own transcript) into a patch unconditionally at the end of every dispatcher/telegram-session run. Confirmed codex already writes `/tmp/codex-events.jsonl`; claude's transcript lives at `~/.claude/projects/.../<session-id>.jsonl` — no new instrumentation needed for the worklog half.
**Design:** `always()` step after "Run agent" in both dispatcher.yml's and telegram-session.yml's `handle` job: `git add -A` + `git diff --cached HEAD > workspace.patch`, no-op if empty (means agent already committed everything); upload via `actions/upload-artifact`; mention in the Telegram summary.

**Q1 — does this only matter on failure?** No — it's unconditional (`always()` + empty-diff no-op), not gated on error detection at all. That's the point: on a normal green run with everything committed, it's a fast no-op: nothing to back up, costs nothing. It only produces output when uncommitted work exists, pass or fail — a backstop independent of any error/pattern matching succeeding.

## 2026-08-07: transcript-secret-exposure-risk — confirmed real, changes the backup-branch plan
**Q2 — is publishing Claude/Codex transcripts dangerous?** Yes, confirmed concretely, not hypothetical: this is exactly why CodeRabbit blocked PR#94 (svsch#117 diagnostics fix, see pruned #93/#117 history) — raw codex event logs can contain `GH_TOKEN`/restored `CODEX_AUTH_JSON` contents, since tool calls/outputs are logged verbatim (cat'd secret files, curl responses with tokens, printed env vars). Claude's session jsonl has the identical problem.
Also checked (new fact, not in earlier design): **the-intern repo is public** (`"private": false`), not private — so the earlier "push to a `workspace-backups` branch" idea is worse than first proposed: that branch would be fully public and permanent in git history, not gated behind any login. GH Actions artifacts on a public repo are also broadly downloadable, not meaningfully private either.
**Why:** any backup mechanism that includes the raw transcript/jsonl risks leaking live credentials to the public internet, permanently (branch) or for 90 days (artifact) — the git-diff patch alone is lower risk (only exposed if the agent itself wrote a secret to a tracked/untracked file) but not zero.
**How to apply:** before building [[workspace-backup-on-every-run]] — either (a) keep the diff-patch backup and drop/redact the raw transcript half, or (b) add secret redaction to the transcript before it's stored, same fix PR#94 needed and never got.
