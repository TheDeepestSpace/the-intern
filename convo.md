## 2026-08-03: answered — "manager" agent design (CI/CodeRabbit nudger) + prompt-injection tiers
User considering a cron manager agent (~every 12h) to auto-dispatch on red CI or unaddressed CodeRabbit threads. CI-failure auto-fix already exists (`handleCheckSuite` in worker/src/index.js, hardcoded instruction via parse-trigger.js ~line 38-44). CodeRabbit-nudge piece is new risk since it's not webhook-triggered — manager would proactively read comment text via API. `ALLOWED_USERS` (worker/src/index.js:46-55, exact-login allowlist) already blocks public drive-by injection via comments (CodeRabbit's bot isn't on it). Recommended mitigation: query structurally only ("has unresolved thread?" boolean from API, never feed raw comment text into manager's own decision-making), dispatch with hardcoded instruction, same pattern as ci_failure. Three-tier injection framing settled: (1) injected text feeds the literal prompt directly — worst case, no role separation (#90 above is a mild real instance); (2) agent reads content via tool call mid-task, lands as tool-result data — lower authority, real but lower-probability risk, backstopped by no-auto-merge + required reviewer, not prevented; (3) structural-only query, comment body never fetched — the only tier that's actually ~zero exposure. Tier 3 is the target for the CodeRabbit check itself; tier 2 is unavoidable once a dispatched session reads the thread to actually fix it. **No issue filed** — pure design/threat-model Q&A, no go-ahead given to file.
