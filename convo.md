## 2026-08-03: svsch multi-panel diagrams — settled on per-module (not per-file), svsch#111 filed+dispatched
Initial pitfalls-only pass (per-file panel idea) superseded same day: user reconsidered and settled on **per-module** panels instead, specifically to avoid the "module instance points to a module in a different file — new window or dropdown-flip?" branching that per-file would force. Per-module: one panel per module identity, reveal-if-exists (like VS Code editors for files), regardless of declaring file — also sidesteps the earlier-found `--list-only` per-file module-filtering problem (no `.file` field until individually loaded) since a module panel only needs its own node. Still-valid pitfalls from the original pass: (1) `DiagramPanel` is a strict singleton today (`extension.ts`+`diagramPanel.ts`), needs real refactor; (2) elaboration has zero caching + its own file watcher per instance — N panels = N concurrent full-project rebuilds, `retainContextWhenHidden:true` keeps every panel's tree+graph alive; (3) no `editor/title` icon-button contributions exist in package.json yet; (4) no "elaborate leaf as instantiated by parent's params" concept — standalone leaf elaboration could mislead. Filed **svsch#111** (https://github.com/TheDeepestSpace/svsch/issues/111) scoped ONLY to extracting elaboration into a shared cached service (the concrete prep step), NOT the panel UI itself — that's future work. Tier 3 is the target for the CodeRabbit check itself; tier 2 is unavoidable once a dispatched session reads the thread to actually fix it. **No issue filed** — pure design/threat-model Q&A, no go-ahead given to file.

## 2026-08-03: answered — textExtractor phase-out plan (svsch), no real UHDM data gap
User wants to phase out textExtractor.ts (perf). Three concrete gaps found: (1) port widths when C++ backend's widthFromPortTypespec/getWidth (lookup_source.inc) returns ""/[0:0] — likely non-ANSI port decl forms; (2) source line/col falling back to module header instead of real decl site — a handle-selection bug in modules.inc (~46-49), vpiLineNo/vpiColumnNo already used elsewhere so data exists in UHDM, just misread; (3) occasional whole bus nodes UHDM's node-builder misses — likely concat/replication expr shapes not pattern-matched in aggregate.inc/expressions.inc. Muxes/always_ff/struct-interface breakout are already fully C++-backend-derived, no regex involved. Recommended: fix these 3 gaps in the C++ backend (bounded, incremental) rather than rewrite. Surveyed alternative libs: Verible already tried and abandoned in this repo (src/parser/veribleExtractor.ts is a dead stub, no elaboration/type resolution); tree-sitter-verilog same limitation (syntax-only); slang (MikePopoloski) is the one real semantic-AST alternative but swapping it in means replacing Surelog+UHDM entirely — a rearchitecture, not recommended unless backend-side fixes prove insufficient.
