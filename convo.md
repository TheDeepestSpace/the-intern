## 2026-08-02: the-intern#80 filed + dispatched — persist-credentials:false regression breaks session-summary push
User asked to investigate a dispatcher failure notification for #78 (run 30761367836). Root cause: PR #68's checkout-hardening commit (81a3625, merged 2026-08-02 18:32 UTC) added `persist-credentials: false` to the **wrong** checkout — the root "Checkout agent-infra" step in dispatcher.yml's `handle` job (~line 239-243). `scripts/manage-summaries.js save` (the "Commit session summary" step, ~line 485-493) runs plain `git push origin summaries/...` with no `working-directory` override, so it operates on that exact root checkout, not `target/`. The `GH_TOKEN: secrets.GITHUB_TOKEN` set on that step is a no-op for auth purposes — raw `git` doesn't read `GH_TOKEN` (that's `gh`-CLI-only); credentials must come from git's persisted extraheader config, which `persist-credentials: false` strips. Confirmed via job log: `fatal: could not read Username for 'https://github.com'`.
- **Impact**: every dispatcher-triggered run since 18:32 UTC today has silently failed to save its session summary — breaks cross-turn continuity for all GH-issue/PR-triggered work (not telegram-session.yml, which doesn't call manage-summaries.js at all).
- **Fix**: remove `persist-credentials: false` from just the `handle` job's checkout (job already has `contents: write` perms, matching the `GH_TOKEN` already set downstream). Leave it in place on `ensure-agent-overlay`/`notify-failure` checkouts — those never push.
- Filed **the-intern#80**, dispatched immediately (high-confidence single-line fix). Check for PR — treat as priority since it's actively degrading every dispatched session right now.
